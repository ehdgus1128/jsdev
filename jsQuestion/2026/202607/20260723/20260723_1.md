## 문제

```javascript
function Demo(name) {
    this.name = name;
}

Demo.prototype.printName = function () {
    console.log(this.name);
}

const obj = new Demo('Happy new year 2024');

obj.printName();
console.log(obj.hasOwnProperty('printName'));
```

### 보기

```
A. Happy new year 2024, false
B. Happy new year 2024, true
C. undefined, false
D. None of these
```

---

# 정답

✅ **A.**

```
Happy new year 2024
false
```

---

# 실행 과정

## 1. 생성자 함수 선언

```javascript
function Demo(name) {
    this.name = name;
}
```

`new Demo()`가 호출되면 객체가 생성되고 `name` 프로퍼티가 추가된다.

생성된 객체

```javascript
obj = {
    name: "Happy new year 2024"
}
```

---

## 2. Prototype에 메서드 추가

```javascript
Demo.prototype.printName = function () {
    console.log(this.name);
}
```

여기서 `printName`은 객체 안에 생성되는 것이 아니라

`Demo.prototype`에 저장된다.

구조

```
Demo.prototype
└── printName()

        ▲
        │ [[Prototype]]

obj
└── name
```

---

## 3. 객체 생성

```javascript
const obj = new Demo("Happy new year 2024");
```

실제로는

```
obj
 ├── name
 └── [[Prototype]]
        │
        ▼
Demo.prototype
```

처럼 연결된다.

---

## 4. printName() 실행

```javascript
obj.printName();
```

JavaScript는 아래 순서대로 찾는다.

1. obj 안에서 printName 검색
2. 없으면 Prototype 검색
3. Demo.prototype에서 발견
4. 함수 실행

이때

```javascript
this === obj
```

이므로

```javascript
console.log(this.name);
```

은

```javascript
console.log(obj.name);
```

과 같다.

출력

```
Happy new year 2024
```

---

## 5. hasOwnProperty()

```javascript
obj.hasOwnProperty("printName")
```

`hasOwnProperty()`는 **자신이 직접 가지고 있는 프로퍼티만 검사한다.**

현재 obj

```
obj
└── name
```

`printName`은

```
Demo.prototype
└── printName
```

에 존재한다.

따라서

```javascript
obj.hasOwnProperty("printName")
```

결과는

```
false
```

---

# 최종 출력

```
Happy new year 2024
false
```

---

# Prototype 체인

```
               Demo.prototype
            ┌──────────────────────┐
            │ printName()          │
            └─────────▲────────────┘
                      │ [[Prototype]]
                      │
                ┌─────┴─────┐
                │    obj     │
                ├────────────┤
                │ name       │
                └────────────┘
```

---

# hasOwnProperty 비교

```javascript
obj.hasOwnProperty("name")
```

결과

```
true
```

왜냐하면 `name`은 obj 자신의 프로퍼티이다.

---

```javascript
obj.hasOwnProperty("printName")
```

결과

```
false
```

왜냐하면 Prototype에 존재하기 때문이다.

---

# 만약 생성자 안에서 메서드를 만들었다면?

```javascript
function Demo(name) {
    this.name = name;

    this.printName = function () {
        console.log(this.name);
    }
}
```

객체는

```
obj
├── name
└── printName()
```

가 된다.

따라서

```javascript
obj.hasOwnProperty("printName")
```

결과는

```
true
```

---

# Prototype을 사용하는 이유

매번 객체마다 함수를 생성하면

```
obj1.printName()
obj2.printName()
obj3.printName()
```

모두 서로 다른 함수 객체가 생성된다.

하지만 Prototype을 사용하면

```
Demo.prototype.printName
```

하나만 생성되어

모든 객체가 공유한다.

장점

- 메모리 절약
- 성능 향상
- JavaScript의 객체지향 방식

---

# 면접 포인트

### Q1. hasOwnProperty()는 무엇을 검사하는가?

→ 객체 자신의 프로퍼티만 검사한다.

---

### Q2. Prototype도 검사하는가?

→ 아니다.

---

### Q3. 메서드는 어디에 두는 것이 좋은가?

→ Prototype에 두는 것이 일반적이다.

---

### Q4. Prototype을 사용하는 이유는?

→ 모든 인스턴스가 하나의 함수를 공유하여 메모리를 절약하기 때문이다.

---

# 핵심 정리

- `new`는 객체를 생성하고 Prototype을 연결한다.
- 메서드는 Prototype에 저장된다.
- 프로퍼티는 객체 자신에게 저장된다.
- `obj.printName()`은 Prototype에서 메서드를 찾는다.
- `hasOwnProperty()`는 Prototype을 검사하지 않는다.
- Prototype은 메모리 절약을 위해 사용된다.
